# Доменный код лежит модулями в app/

Laravel по умолчанию раскладывает код по техническим слоям: все модели в `app/Models`, все контроллеры в `app/Http/Controllers`. Мы вместо этого группируем код по доменным модулям — `app/<Module>/` рядом с техническими `Http/` и `Providers/`, со слоями `Domain/`, `Application/`, `Infrastructure/` внутри. Причина: доменных областей в сервисе немного и они хорошо очерчены, а по техническим папкам они размазываются, и границу между ними становится не видно.

## Consequences

- `php artisan make:*` кладёт файлы в дефолтные места. После генерации их нужно переносить в модуль и править неймспейс. Автозагрузка при этом не меняется: PSR-4 `App\` уже указывает на `app/`.
- Модуль не обращается к внутренностям другого модуля напрямую — только через его `Application`.
- Blade-шаблоны остаются в `resources/views/`, а не переезжают в модули: view-namespace на модуль потребовал бы провайдера и префиксов в каждом `view()`, а стандартные инструменты Laravel с дефолтным путём работают без настройки.
- Роуты остаются в общем `routes/web.php`. Отдельные файлы роутов на модуль окупаются, когда модулей много и они переиспользуются между приложениями.
